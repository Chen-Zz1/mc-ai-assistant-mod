# Security reporting

Do not post API keys, private conversations, player identifiers, configuration dumps or operational addresses in a public issue. Use GitHub's private vulnerability reporting on the eventual project repository if the maintainer has enabled it. If unavailable, open a content-free request for a private reporting channel; provide sensitive details only after a channel is arranged. No private reporting address is bundled in this source snapshot.

For an exposed key, revoke/rotate it at the provider and review usage; removing it from the latest source file does not erase history or copies. Maintainers should audit source, history, release artifacts and issue attachments before publication. This beta has automated tests and a scoped release-data audit, not an independent security certification.
